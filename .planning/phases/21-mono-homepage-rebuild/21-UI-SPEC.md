## Spacing Scale

The sketch's `--space-*` scale (`mono.css`) is numerically identical to Tailwind v4's
default spacing scale — no custom spacing tokens are needed. Use native Tailwind
utilities throughout.

| Token | Value | Tailwind utility | Usage |
|-------|-------|-------------------|-------|
| 2xs | 4px | `-1` | Icon/glyph gaps |
| xs | 8px | `-2` | Compact inline gaps (e.g. `gap-2`) |
| sm | 12px | `-3` | Terminal row internal padding |
| md | 16px | `-4` | Default gap between grid columns in a row |
| lg | 24px | `-6` | Row internal gap (`.a-row` `gap-6`), section label to content |
| xl | 32px | `-8` | Row vertical padding (`.a-row` `py-8`) |
| 2xl | 48px | `-12` | Space between a section's label and its first row |
| 3xl | 64px | `-16` | Space between major bands (mobile) |
| 4xl | 96px | `-24` | Space between major bands (desktop, secondary) |
| 5xl | 128px | `-32` | Hero top/bottom padding (desktop), space between major bands (desktop, primary) |
| 6xl | 192px | `-48` | Reserved; not used in this phase's layout (sketch's largest step) |

Content max-width: `1180px` (matches the existing `.wrap` class already shipped —
reuse it, do not redefine). Gutter: `clamp(22px, 6vw, 88px)` (existing `.wrap`
padding, unchanged).

Exceptions: none. At 375px, section/band vertical spacing steps down one rung (e.g.
`py-32`→`py-16` on the hero, `mt-12`→`mt-6` between label and first row) — see
Responsive Contract for the full collapse spec.

MO-05 and the sketch's `.ttl` semibold row-title convention.

## Color

This is a **zero-accent, two-value system by explicit design lock** (MO-02). The
generic 60/30/10 dominant/secondary/accent model does not apply — there is no
accent color anywhere, on purpose. Contrast and emphasis come entirely from
**inversion** (a solid black block on white) and **type weight**.

| Role | Value | Usage |
|------|-------|-------|
| Ground (100% of page background) | `#ffffff` (`--color-bg`) | The entire page — HP-04 requires exactly one continuous ground, no exceptions |
| Ink | `#000000` (`--color-text`) | All body/display text at rest |
| Dim / muted ink | `rgba(0,0,0,0.66)` / `rgba(0,0,0,0.60)` (`--color-text-dim` / `--color-text-muted`) | Descriptions, mono labels, secondary meta |
| Hairline | `rgba(0,0,0,0.14)` (`--color-border`) | Row top-rules, terminal header rule — the load-bearing structural element per Phase 20's own risk note |
| Firm rule | `rgba(0,0,0,0.32)` (`--color-border-strong`) | Reserved; not used in this phase's new CSS (existing shipped uses elsewhere are untouched) |
| Invert block | `#000000` (`--color-invert`) | The **only** hover/emphasis surface on the page: full-row invert on Building rows, full-row invert on Writing terminal rows |
| Inverse ink | `#ffffff` (`--color-text-inverse`) | Text on an inverted row |
| Accent | **none — zero hits anywhere** | N/A. Any hex/rgba outside the pure-mono ladder above is a defect (MO-02) |
| Destructive | not applicable | No destructive actions exist on the homepage in this phase |

Accent reserved for: **nothing.** There is no accent color in this design. Any
executor instinct to add "one small accent detail" is out of scope and must be
rejected — this is the entire point of the v4 lock.

## Section-by-Section Design Contract

### 1. Hero (HP-01)

Type only. No `<Image>`, no portrait carousel, no marker block, no `.hero-ticker`,
no `.statustag` pulsing dot.

- Wrapper: `.wrap` (existing, max-width 1180px), padding `py-32` desktop / `py-16`
  mobile (sketch: `var(--space-48) 0 var(--space-32)` — adapted down since
  `--space-48`/192px is unused elsewhere in the shipped scale; `py-32`/128px top is
  the closest already-used step and reads correctly against the rest of the page).
- Content, top to bottom:
  1. Mono eyebrow label: `Monty Singer` — `text-xs`, `font-mono`, `tracking-[0.12em]`, uppercase, `--color-text-muted`.
  2. `<h1>`: hero copy above. `text-3xl` desktop / `text-2xl` mobile, `font-display` weight 800, `leading-[0.95]`, `tracking-[-0.03em]`, `max-w-[14ch]`.
  3. Subtitle `<p>`: hero copy above. `text-base`, `font-sans` weight 300 **[Implementer Discretion — sketch uses weight 300; that weight is loaded (`300` is in the `next/font` weight array) so honor it]**, `leading-[1.6]`, `--color-text-dim`, `max-w-[46ch]`.
  4. Meta row: 3-column grid (`grid-cols-3` desktop, `grid-cols-1` mobile), `gap-8`, `border-t border-border pt-4 mt-16`. Each cell: mono label (`text-xs`, muted, tracked) above a value line (`text-sm`).
- No CTA button anywhere in the hero. The `Writes → Monty Monthly` meta cell is
  informational text, not a link-styled button (its `X`/`LinkedIn`/`Email` siblings
  ARE plain text links with no button chrome — this hero never uses filled-button
  styling at all).
- Photos may exist deeper on the page (none currently do, post-rebuild — see
  Component Disposition) but never in this hero, explicitly (HP-01).

### 2. Building index (HP-02)

Row anatomy (desktop), from `.a-row` in the sketch:

- Grid: `grid-template-columns: 64px 1fr 200px 90px` — numeral / title / description / status.
- Gap: `gap-6` (24px). Padding: `py-8` (32px) top/bottom, `0` left/right (bleeds to
  the row's own hover overlay, not the `.wrap` padding). `align-items: baseline`.
- Top rule on every row: `border-top: 1px solid var(--color-border)`. Last row also
  gets a `border-bottom` to close the list.
- Cell styling:
  - `.num` (`001`, `002`, `003`...): `text-xs`, `font-mono`, `--color-text-muted`, `tracking-[0.12em]`. **Zero-padded three digits, always** — `String(n).padStart(3, "0")`, never `1.` or `01`.
  - `.ttl` (title): `text-2xl` desktop / `text-xl` mobile, `font-sans` weight 600, `tracking-[-0.02em]`.
  - `.dsc` (description): `text-sm`, `--color-text-dim`, `leading-[1.5]`.
  - `.status` (rightmost column — "Current" / "Archived" / a year): `text-xs`, `font-mono`, `--color-text-muted`, right-aligned.
- **Row content (Implementer Discretion — recommended default, since neither
  CONTEXT.md nor the sketch specify a Notion binding for this exact section):**
  - Row `001` = **Prometheus**, hardcoded (title "Prometheus", description "AI
    integrations and education. Practical leverage, not hype.", status "Current",
    `href="https://prometheus.today"` with `target="_blank" rel="noopener
    noreferrer"`). This consolidates the old `section-building.tsx` narrative beat
    into row 1.
  - Rows `002`+ = the existing `getFeaturedProjects()` Notion call (already wired in
    `page.tsx`, currently feeding the now-deleted `SectionWork` grid) — one row per
    featured project, `title`/`description` from Notion, status column = the
    project's first tag or its `lastEdited` year, `href="/building/{slug}"`. This
    reuses real, already-fetched data rather than guessing at a fixed "CULTIVATE /
    This site" list, and keeps the index truthful as Monty's Featured set changes in
    Notion.
  - A final static row reading `This site` / "Notion-backed, built by hand, quietly
    over-engineered." / status "Ongoing" **may** be appended after the Notion rows —
    it is factually true (verifiable, not a guess) and matches the sketch exactly,
    but it is optional. If Notion's Featured set already includes an entry for the
    site itself, do not duplicate it.
- **Hover = full-row inversion**, the site's only hover language (HP-02):
  - Implementation: an absolute pseudo-element (`::before`, `inset: 0 -20px`, so it
    bleeds slightly past the row's own edges) with `background: var(--color-invert)`,
    `opacity: 0`, `transition: opacity 150ms ease`. On `:hover`, `opacity: 1`.
  - Simultaneously, every text child (`num`, `ttl`, `dsc`, `status`) transitions
    `color` to `var(--color-text-inverse)`.
  - **Full-row invert, not tight-row** — the overlay must span the row's full width
    including its padding bleed, exactly as in the sketch. A tight invert that hugs
    only the text was explicitly rejected (reads like a glitch at speed).
  - Duration: `150ms`, sourced directly from the sketch's own `.a-row::before`
    transition (`opacity .15s`) — this is the reference implementation's authored
    value for this specific element, taking precedence over Phase 20 D-09's general
    120ms guidance for other (non-index-row) block surfaces.
  - **Keyboard equivalent [Implementer Discretion — required, not optional]:** the
    row's `:focus-visible` state must trigger the identical inverted appearance
    (same `::before` opacity + text color rules, scoped to `:focus-visible` in
    addition to `:hover`). The focus **ring** itself must use `outline-color:
    currentColor` (not a hardcoded `var(--color-invert)`) with `outline-offset:
    2px`, so the ring is black on the row's normal white state and automatically
    becomes white once the row inverts — this is a deliberate, documented override
    of Phase 20 D-10's site-wide `outline: 2px solid var(--color-invert)` rule,
    which would otherwise render an invisible black-on-black ring on an inverted
    row. Scope this override to `.a-row` only; leave D-10's global rule untouched
    everywhere else.
  - **Touch [Implementer Discretion]:** gate the hover rule with `@media
    (hover: hover)` so coarse-pointer devices don't get stuck mid-invert on tap.
    Rows are plain navigational links; a tap should simply navigate. No sticky
    invert state is required on touch — the row's static (non-inverted) appearance
    must remain fully legible and tappable on its own (minimum 44px effective touch
    target height, satisfied by the row's own `py-8` padding plus its `text-2xl`
    title line height).

### 3. Writing list (HP-03)

Terminal register — the **only** mono-type surface on the page (this is what makes
it read as a log rather than a pitch).

- `.e-term` wrapper: `font-mono`, `text-sm`, `line-height: 1.85`.
- Header (`.hd`): literal text `~/writing`. `text-xs`, `--color-text-muted`,
  `tracking-[0.12em]`, uppercase, `padding-bottom: 12px` (`pb-3`), `margin-bottom:
  16px` (`mb-4`), `border-bottom: 1px solid var(--color-border)` — **this single
  rule is the entire "frame."**
- **No box, no 2px border around the block.** Revision 2 explicitly removed the
  frame — it read as a widget bolted onto the page. The block sits directly on the
  paper like every other section, exactly like `01 — Building`.
- Each post row (`.e-post`): grid `104px 1fr 92px` (date / title / read-time), `gap-4`
  (16px), `align-items: baseline`, `padding: 5px 8px`, `margin: 0 -8px` (so the hover
  bleed matches the row's own negative-margin trick, keeping content visually
  aligned with the header rule above it).
  - `.dt` (date, flush left): `--color-text-muted`. Format `YYYY-MM` (matches the
    104px column width and the sketch's exact date format — do not use a full
    "July 2, 2026" date here, that belongs to `/writing`'s own card grid, not this
    compact log).
  - Title (middle column): plain ink, `text-sm`, no special treatment beyond the
    surrounding mono context.
  - `.rd` (read time, flush right): `--color-text-muted`, e.g. `6 min`.
- **Content — merge of two already-fetched sources, sorted newest-first, capped at 5
  rows [Implementer Discretion — recommended default]:**
  - Monty Monthly issues from `fetchMontyMonthlyIssues()` (already fetched in
    `page.tsx`) — date from `issue.pubDate`, title from `issue.title`, read time via
    `estimateReadingTime(issue.description)` (same lightweight word-count estimate
    the `/writing` page already uses for its own reading-time gaps — see the
    "real reading time" future requirement below).
  - Blog essays from `getPublishedPosts()` (`src/lib/notion.ts`, already used by
    `/writing`) — date from `post.date`, title from `post.title`, read time via
    `estimateReadingTime(post.description)` (matching `writing/page.tsx`'s own
    documented D-09 pattern: "Lightweight reading time estimate... to satisfy D-09
    without extra API calls").
  - Interleave both lists by date descending, take the first 5, render as `.e-post`
    rows, then the `all posts →` link to `/writing`.
  - **Known limitation, already tracked:** read time is a word-count estimate, not
    a real Notion-authored value. This is explicitly listed under REQUIREMENTS.md
    "Future Requirements (deferred)" — do not treat it as a gap this phase must
    close.
- **Hover = full-row inversion**, identical mechanism to the Building rows
  (`background: var(--color-invert)`, text → `var(--color-text-inverse)` /
  `var(--color-text-inverse-dim)` for the muted date/read-time cells). Same 150ms
  timing, same `:focus-visible` + `currentColor` outline override as Building rows.
- **No cursor glyph in this phase's shipped Writing band.** The sketch's blinking
  cursor lives only in variant B (not built), and variant E's terminal block does
  not render one at all. If a future revision adds a cursor glyph, it must be
  static (a literal `_` character, no `@keyframes` blink) — a perpetual blink is
  the same attention-grab as the pulsing status dot this milestone already killed.

### 4. Continuous ground (HP-04)

- Exactly one `.band` treatment for the entire page: `background: var(--color-bg)`
  (`#ffffff`), `color: var(--color-text)` (`#000000`). Delete every `band-dark`
  class from `explorative-homepage.tsx` and stop applying `.band.band-dark`
  anywhere on the homepage.
- Delete (or leave dormant/unreferenced) the `.band.band-dark` CSS rule's
  `background: #000000` behavior as a *homepage* consumer — it currently exists in
  `globals.css` purely to serve this now-retired alternation. Do not delete the CSS
  rule itself if any other route still references it (grep before removing; if the
  homepage was its only consumer, removing the rule is a welcome cleanup but not
  required by this phase's success criteria).
- `.band.hero-band { background: var(--hero-bg) }` — since the new hero no longer
  needs a distinct cream/tinted background (HP-04 forbids any tonal variation), stop
  applying `hero-band` on the new `Hero` section, or repoint `--hero-bg` to
  `#ffffff` if the class is kept for structural reasons. Either satisfies HP-04;
  Phase 20 context already flagged this exact fork as an open discretion call.
- Separation between sections comes from three things only, per HP-04: (1) a single
  `border-top: 1px solid var(--color-border)` hairline between adjacent `.band`
  elements (the existing `.band + .band` rule already does this — keep it), (2)

## Accessibility Contract

Contrast is not the concern in a pure black-on-white system (every ink/background
pairing here is either `21:1` (`#000` on `#fff`) or the already-WCAG-AA-audited
`--color-text-muted` at `0.60` opacity, `5.74:1` — Phase 20 D-07). This phase's
accessibility work is entirely about **state visibility without color**.

1. **Focus rings without an accent color.** Global rule stays Phase 20 D-10:
   `:focus-visible { outline: 2px solid var(--color-invert); outline-offset: 2px }`
   everywhere **except** `.a-row` and `.e-post` (Building/Writing rows), which use
   `outline-color: currentColor` instead (documented above under Building Index) so
   the ring survives being on top of its own inverted black background. This is a
   scoped, deliberate override — not a global change to D-10.
2. **Inverted-row hover has a keyboard equivalent.** Both `.a-row` and `.e-post`
   apply their full inversion on `:focus-visible` identically to `:hover` — a
   keyboard user tabbing through the index/terminal list sees the exact same black
   block a mouse user sees on hover, not just a ring with no fill change. Required,
   specified above per row type.
3. **`prefers-reduced-motion`.** The one surviving fade (`.reveal`) already has both
   a CSS media-query guard and a JS guard in `scroll-reveals.tsx` (existing
   pattern, retained). Row-invert hover/focus states are instant (150ms
   color/background transitions, not translate/opacity ambient motion) and are not
   required to be disabled under reduced-motion — only looping/auto-playing motion
   needs a reduced-motion guard, and this phase has none beyond the one fade.
4. **Touch targets.** Every Building row and every Writing terminal row is a single
   `<a>` spanning the row's full padded height (`py-8` / `padding: 5px 8px`
   respectively) — both exceed the 44px minimum once title-line-height is
   accounted for; verify at 375px per the Responsive Contract's test requirement.
5. **Semantic structure.** Section labels (`01 — Building`, `02 — Writing`,
   `03 — Things I Love`) should be real headings (`<h2>` or a labelled `<section
   aria-label="...">`) even though they're styled as small mono tags — do not drop
   to a bare `<span>` with no heading semantics, since these are the page's only
   section landmarks post-rebuild (no `RailBox`, no dark-band visual break to lean
   on for orientation).
