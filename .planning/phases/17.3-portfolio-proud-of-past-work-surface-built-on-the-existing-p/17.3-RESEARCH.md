# Phase 17.3: Portfolio — Research

**Researched:** 2026-07-02
**Domain:** Notion projects pipeline, curation mechanism, route architecture
**Confidence:** HIGH

## Summary

Phase 17.3 requires building a curated "portfolio surface" that showcases selected proud-of past work, sourced from the existing Notion projects pipeline. The good news: the infrastructure for this already exists. The Notion Projects database has a `Featured` boolean checkbox, and `notion-projects.ts` already exports a `getFeaturedProjects()` function. The delta is minimal — create a new portfolio route that filters by the `Featured` flag and link the homepage "Selected Work" section to it.

The existing `/projects` page uses `getPublishedProjects()` to show the full chronological archive. The portfolio surface will use `getFeaturedProjects()` to show only the curated "proud of" subset. Both routes reuse the same Card/YearBlock visual pattern, ISR strategy (1800s revalidation), and defensive empty-state handling.

**Primary recommendation:** Create a new `/portfolio` route that mirrors the structure of `/projects` but filters by `Featured: true` in the Notion database. Update the homepage `SectionWork` component to link to `/portfolio` instead of (or in addition to) `/projects`. Reuse the existing layout, components (Card, YearBlock, PageHero), and ISR patterns without duplication.

### Pattern 4: Year-Grouped Card Grid Layout

**What:** Group projects by year using `lastEdited` date, then render each year's projects in a responsive grid of Card components. The grid uses `grid-template-columns: repeat(auto-fill, minmax(260px, 1fr))` for mobile-to-desktop fluidity.

**When to use:** Displaying a large collection of items (10+) that benefit from time-based organization.

**Example:**

```typescript
function groupProjectsByYear(projects: Project[]): Map<number, Project[]> {
  const groups = new Map<number, Project[]>();
  for (const project of projects) {
    if (!project.lastEdited) continue;
    const year = new Date(project.lastEdited).getUTCFullYear();
    if (Number.isNaN(year)) continue;
    const bucket = groups.get(year) ?? [];
    bucket.push(project);
    groups.set(year, bucket);
  }
  return new Map([...groups.entries()].sort(([a], [b]) => b - a));
}

// In JSX:
<div className="grid [grid-template-columns:repeat(auto-fill,minmax(260px,1fr))] gap-px bg-[var(--color-border)] border border-[var(--color-border)]">
  {yearProjects.map((project) => (
    <Card
      key={project.id}
      href={`/projects/${project.slug}`}
      title={project.title}
      blurb={project.description}
      kicker={project.tags?.[0]}
      coverSrc={project.image ? `/api/notion-cover?pageId=${project.id}` : undefined}
      coverAlt={project.image ? project.title : undefined}
    />
  ))}
</div>
```

**Source:** [VERIFIED: codebase] `src/app/projects/page.tsx` lines 25–36 (grouping logic), lines 82–107 (render pattern).

### Anti-Patterns to Avoid

- **Don't create a separate Notion database for portfolio projects:** The `Featured` flag is the single source of truth. Duplicating projects across databases creates sync issues and maintenance debt.
- **Don't hard-code the portfolio list in code:** This breaks the Monty → Notion workflow. All curation must live in the Notion database; code only consumes it.
- **Don't fetch *all* projects and filter in JavaScript:** It wastes bandwidth and API quota. Let Notion do the filtering via the `.databases.query()` filter parameter (which `getFeaturedProjects()` already does correctly).
- **Don't forget the empty state:** If a Notion query fails or returns zero results, the page must render gracefully, not crash or show a blank white screen.

## Don't Hand-Roll

|---------|-------------|-------------|-----|
| Notion filtering | Custom JavaScript filter of all projects | `getFeaturedProjects()` in notion-projects.ts | SDK query filters at the source; respects Notion's rate limits; pagination handled |
| Image proxying for Notion covers | Custom image fetch handler | Existing `/api/notion-cover` route | Already handles Notion auth, caching, fallbacks; reuse it |

## Common Pitfalls

### Pitfall 1: Forgetting the Featured Property in Notion

**What goes wrong:** The `/portfolio` page fetches projects but shows an empty list even though projects exist, because none of them have the `Featured` checkbox set to true in Notion.

**Why it happens:** Notion Projects database must be manually curated — each project Monty wants in the portfolio must have its `Featured` checkbox enabled. The code can't infer intent; it relies on explicit flags.

**How to avoid:** 
- Document in the phase plan that Monty must set `Featured: true` on projects *before* the portfolio goes live.
- Verify in testing that at least 2–3 test projects have `Featured: true` in the Notion workspace.
- Include a checkpoint in the plan: "Verify Notion Projects database has 3+ featured projects" (HUMAN verification).

**Warning signs:** Portfolio page renders but shows "No featured projects yet" even though projects clearly exist in the `/projects` archive.

### Pitfall 2: ISR Revalidation Lag

**What goes wrong:** Monty updates a project's Featured status in Notion, but the portfolio page still shows the old list for 30 minutes.

**Why it happens:** ISR revalidates on a fixed schedule (every 1800 seconds). Changes to Notion are not immediately reflected; there's a ~30-minute window of staleness.

**How to avoid:** 
- Document this behavior in the phase completion notes so Monty expects the lag.
- If real-time updates are needed later, that's a future phase (on-demand revalidation via Notion webhook — not in scope for 17.3).
- For now, ISR 30 minutes is acceptable (it's the project standard per STATE.md carryforward).

**Warning signs:** Monty makes a Notion change, deploys to Vercel, but the page doesn't immediately update.

### Pitfall 3: Mixing `/portfolio` and `/projects` Links on Homepage

**What goes wrong:** The homepage SectionWork links to both `/portfolio` and `/projects`, causing confusion about which is the "main" entry point. Success Criterion 2 says "The homepage 'selected work' section links into the portfolio" — but should the old `/projects` link disappear or stay?

**Why it happens:** Unclear semantics: is `/projects` the archive or a secondary link? Is `/portfolio` the primary or the only entry point?

**How to avoid:** 
- Phase 17.3 only requires that SectionWork link to `/portfolio` (Success Criterion 2). Whether `/projects` link stays or is removed is an Information Architecture decision.
- This phase depends on Phase 17.1 (Homepage), not Phase 17.2 (IA). Phase 17.2 may have addressed this, but 17.3 doesn't depend on it.
- Recommendation: Update the plan to include a checkpoint: "Confirm with user whether `/projects` link stays on homepage alongside `/portfolio` or is removed." (D-01 decision for the phase plan).

**Warning signs:** Planner creates conflicting link structures; UX testing shows users confused about which surface is authoritative.

### Pitfall 4: Cover Image Proxy URL Generation

**What goes wrong:** Portfolio projects fail to load cover images because the `project.image` property is null or malformed.

**Why it happens:** Not all projects in Notion have cover images. The Card component's `coverSrc` prop expects a valid URL or undefined — if it receives null or an empty string, the image proxy may break.

**How to avoid:**
- Reuse the exact conditional logic from `/projects/page.tsx` lines 94–99: only pass `coverSrc` if `project.image` is truthy.
- Mirror this pattern in the portfolio page:
  ```typescript
  coverSrc={project.image ? `/api/notion-cover?pageId=${project.id}` : undefined}
  ```
- This is already a working pattern; don't invent a new one.

**Warning signs:** Console errors about malformed image URLs; broken image placeholders in the grid.

```typescript
// src/app/portfolio/page.tsx
import { Fragment } from "react";
import type { Metadata } from "next";
import { getFeaturedProjects, type Project } from "@/lib/notion-projects";
import { RuleStrong } from "@/components/editorial/rule-strong";
import { YearBlock } from "@/components/editorial/year-block";
import { PageHero } from "@/components/v3/page-hero";
import { Card } from "@/components/v3/card";

export const revalidate = 1800; // ISR: revalidate every 30 minutes

export const metadata: Metadata = {
  title: "Portfolio | Monty Singer",
  description:
    "Selected projects and products Monty Singer is proud of — built through Prometheus and independent work.",
  alternates: { canonical: "/portfolio" },
  openGraph: {
    title: "Portfolio | Monty Singer",
    description:
      "Selected projects and products Monty Singer is proud of — built through Prometheus and independent work.",
    url: "/portfolio",
    type: "website",
  },
};

function groupProjectsByYear(projects: Project[]): Map<number, Project[]> {
  const groups = new Map<number, Project[]>();
  for (const project of projects) {
    if (!project.lastEdited) continue;
    const year = new Date(project.lastEdited).getUTCFullYear();
    if (Number.isNaN(year)) continue;
    const bucket = groups.get(year) ?? [];
    bucket.push(project);
    groups.set(year, bucket);
  }
  return new Map([...groups.entries()].sort(([a], [b]) => b - a));
}

export default async function PortfolioPage() {
  let projects: Project[] = [];
  try {
    projects = await getFeaturedProjects();
  } catch {
    // Defensive: Notion API failure renders empty-state, no crash
  }

  const projectsByYear = groupProjectsByYear(projects);
  const yearEntries = [...projectsByYear.entries()];

  return (
    <>
      <section className="px-6 md:px-40">
        <PageHero
          title="Portfolio"
          crumb="Home / Portfolio"
          sub="A selection of projects I'm proud of — built through Prometheus and independent work."
        />
      </section>

      <RuleStrong />

      <section className="px-6 md:px-40">
        {yearEntries.length === 0 ? (
          <p className="text-center py-12 text-[var(--color-text-muted)]">
            No featured projects yet. Check back soon.
          </p>
        ) : (
          <div className="-mx-6 md:-mx-40">
            {yearEntries.map(([year, yearProjects], i, arr) => (
              <Fragment key={year}>
                <YearBlock year={year}>
                  <div className="grid [grid-template-columns:repeat(auto-fill,minmax(260px,1fr))] gap-px bg-[var(--color-border)] border border-[var(--color-border)]">
                    {yearProjects.map((project) => (
                      <Card
                        key={project.id}
                        href={`/projects/${project.slug}`}
                        title={project.title}
                        blurb={project.description}
                        kicker={project.tags?.[0]}
                        coverSrc={
                          project.image
                            ? `/api/notion-cover?pageId=${project.id}`
                            : undefined
                        }
                        coverAlt={project.image ? project.title : undefined}
                      />
                    ))}
                  </div>
                </YearBlock>
                {i < arr.length - 1 && <RuleStrong />}
              </Fragment>
            ))}
          </div>
        )}
      </section>

      <RuleStrong />
    </>
  );
}
```
