## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Notion API -> portfolio/page.tsx | Notion project data (titles, descriptions, image URLs) arrives as structured data from the official SDK; consumed server-side only |
| portfolio/page.tsx -> Browser | Rendered HTML with project titles and descriptions as JSX text content |
| Browser -> /api/notion-cover | Image proxy receives pageId query param constructed server-side from project.id |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-17.3-01 | Tampering | Notion project title/description in Card JSX | accept | Next.js JSX renders text children as escaped text nodes by default; Card component uses {project.title} and {project.description} as JSX text (no dangerouslySetInnerHTML); no XSS path |
| T-17.3-02 | Elevation of Privilege | /api/notion-cover pageId parameter | accept | pageId is derived from project.id in Notion API response (server-side); visitors cannot forge the parameter from the portfolio page; the proxy route was hardened in Phase 2 and is not modified here |
| T-17.3-03 | Information Disclosure | NOTION_TOKEN / NOTION_PROJECTS_DATABASE_ID | accept | getFeaturedProjects() is a server-only function in notion-projects.ts; portfolio/page.tsx is a Server Component with no "use client"; secrets are never serialized to client bundles |
| T-17.3-SC | Tampering | npm/pip/cargo installs | accept | No new packages installed in this plan; existing @notionhq/client and next are already audited |
