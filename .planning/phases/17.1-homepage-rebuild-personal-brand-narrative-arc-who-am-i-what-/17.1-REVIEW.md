## Warnings

### WR-01: Newsletter Carousel Cards Render as Active Links to `#` (Page Top)

**File:** `src/components/home/section-newsletter.tsx:80-92`

**Issue:** All three newsletter issue objects pass `href: "#"` to `NewsletterCarousel`. The carousel component treats any truthy `href` as a link and renders `<Link href={issue.href}>`. With `href="#"`, this produces three clickable card elements that navigate to the fragment `#` on click — which adds a hash to the URL and scrolls the page to the top. The apparent intent was placeholder non-interactive cards. The `NewsletterCarousel` component already implements the correct non-interactive path: when `href` is absent/undefined, it renders a plain `<div>`. Using `"#"` accidentally bypasses that path.

**Impact:** Visitors clicking any of the three carousel cards navigate to `#` instead of doing nothing (or going to Substack). Confusing UX on the primary newsletter engagement section.

**Fix:** Remove the `href` field from all three issue objects (or set it to `undefined`) so `NewsletterCarousel` renders non-interactive `<div>` cards. When real Substack issue URLs are available, populate them directly:

```tsx
// Current (broken — navigates to page top on click)
{
  title: "Vol. 1: Builders, Breakers, Believers",
  date: "Jun 2026",
  href: "#",
},

// Fixed — renders as non-interactive div (placeholder until real URLs exist)
{
  title: "Vol. 1: Builders, Breakers, Believers",
  date: "Jun 2026",
  // href omitted — NewsletterCarousel renders <div> when href is absent
},

// Or when Substack issue URLs exist:
{
  title: "Vol. 1: Builders, Breakers, Believers",
  date: "Jun 2026",
  href: "https://montymonthly.substack.com/p/vol-1-builders-breakers-believers",
},
```

### IN-02: Newsletter CTA Button Opens External Substack Link Same-Tab

**File:** `src/components/home/section-newsletter.tsx:98`

**Issue:** `<Button href="https://montymonthly.substack.com" accent>See the issues →</Button>` passes an external URL to `Button`. The `Button` component's type has no `target` or `rel` props — it renders `<Link href={href}>` unconditionally, which means the link opens same-tab. Every other Substack link on the page uses `target="_blank"` (the hero link in `explorative-homepage.tsx:43-45` and the footer link in `section-footer.tsx:75-79`). No security concern applies (noopener/noreferrer is only relevant for new-tab links), but the UX is inconsistent: the CTA button navigates users away from the site rather than opening a new tab.

**Fix (option A — preferred, no component change):** Replace `Button` with a plain `<a>` element styled to match:

```tsx
<a
  href="https://montymonthly.substack.com"
  target="_blank"
  rel="noopener noreferrer"
  className="inline-flex items-center gap-2 font-mono text-sm uppercase tracking-[0.08em] px-6 py-[14px] border transition-[background,color] duration-150 cursor-pointer bg-accent border-accent text-bg hover:bg-transparent hover:text-accent"
>
  See the issues →
</a>
```

**Fix (option B — component change):** Add optional `target` and `rel` props to `Button` in `src/components/v3/button.tsx` and forward them to `<Link>`.

### IN-03: Heading Level Jump: `h1` → `h4` in Footer (Pre-Existing)

**File:** `src/components/home/section-footer.tsx:31,52,70,110`

**Issue:** The four footer column headings ("Site", "More", "Elsewhere", "Connect") are `h4` elements. The page heading hierarchy is: `h1` (hero) → `h2` "Monty Monthly" (SectionNewsletter) → `h4` (footer columns). No `h2` or `h3` exists within the footer section. Screen reader users navigating by heading level will jump from the `h2` in SectionNewsletter directly to `h4`s in the footer. This is a pre-existing structure — only the "Contact" → "Connect" text was changed in this phase.

**Fix:** Promote the footer column headings from `h4` to `h3`, or add an invisible `h2` to the footer section that screen readers can use as a landmark:

```tsx
{/* Invisible heading for screen reader navigation */}
<h2 className="sr-only">Site navigation</h2>
```

### IN-04: Inconsistent Element Type for `prometheus.today` Across Two Files

**File:** `src/components/home/section-building.tsx:30` / `src/components/home/section-work.tsx:31`

**Issue:** The same external URL (`https://prometheus.today`) is linked differently in two sibling files:
- `section-building.tsx` uses a native `<a>` element (no `Link` import)
- `section-work.tsx` uses Next.js `<Link>` component

Both correctly include `target="_blank" rel="noopener noreferrer"`. There is no behavioral difference for external URLs — Next.js `<Link>` renders `<a>` for external hrefs. Both approaches are valid, but the inconsistency between adjacent section files makes the codebase pattern harder to read.

**Fix:** Standardize on Next.js `<Link>` (the established pattern in this codebase and used in `section-work.tsx`, `section-footer.tsx`, and `explorative-homepage.tsx`). Add the `Link` import to `section-building.tsx` and replace the `<a>` with `<Link>`:

```tsx
// section-building.tsx — replace <a> with <Link>
import Link from "next/link";
// ...
<Link
  href="https://prometheus.today"
  target="_blank"
  rel="noopener noreferrer"
  className="..."
>
```
