# Phase 17.1 Plan 2: SectionWork + SectionLoves New Teaser Sections Summary

**One-liner:** Created two new Server Component teaser sections (SectionWork and SectionLoves) with hardcoded portfolio/loves content and wired them into the orchestrator in the final D-06 narrative arc order, retiring the SectionWriting render path.

## What Was Built

### section-work.tsx (new)
Server Component (no `"use client"`) implementing section 3 of the D-06 narrative arc:
- `SectionLabel` numeral `"03"` with label "Selected Work"
- Prose paragraph: "A handful of things I have built. More lives at Prometheus."
- Two work items rendered as direct BigList-styled `Link` elements:
  - Prometheus (`https://prometheus.today`, `sig-out` outline treatment, `target="_blank" rel="noopener noreferrer"`, tag: CURRENT)
  - Projects (`/projects`, `sig` filled treatment, tag: ARCHIVE)
- Button `href="/projects"` "All work" below the list
- Section wrapper: `min-h-dvh flex flex-col justify-center px-[8vw] py-[15vh]` (matches SectionBuilding)

**Key decision:** The Prometheus link is rendered as a direct `<Link>` instead of through BigList because `BigList`'s `Item` type has no `target` or `rel` fields — the component cannot forward these anchor attributes. Rendering directly (with identical BigList CSS classes) satisfies `rel="noopener noreferrer"` per T-17.1-02 threat mitigation.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Missing Critical Functionality] BigList cannot forward rel="noopener noreferrer" — rendered Prometheus as direct Link**
- **Found during:** Task 1 (reading src/components/v3/big-list.tsx)
- **Issue:** The BigList `Item` type only defines `label`, `href`, `tag`, and `outline`. It renders items via `<Link>` internally but exposes no `target` or `rel` passthrough. The plan anticipated this and prescribed using a "prose Link element" as fallback.
- **Fix:** Rendered both work items as direct `<Link>` elements using the exact same CSS classes as BigList (matching visual appearance). The Prometheus link carries `target="_blank" rel="noopener noreferrer"`. The plan's threat model (T-17.1-02) and acceptance criteria both required this.
- **Files modified:** src/components/home/section-work.tsx
- **Commit:** c327910
