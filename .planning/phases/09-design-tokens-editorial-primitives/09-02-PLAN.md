- File header: no 'use client' directive (D-11 — Server Component).
- Named export `Rule` typed as `(props?: { className?: string }) => JSX.Element`.
- Render an `<hr>` element with `aria-hidden="true"` (decorative), default classes `h-px w-full border-0 bg-rule`, and a `className` prop merged at the end so consumers can add `my-Npx` spacing utilities without overriding color/thickness.
- Use the `cn` helper from `@/utils/cn` to merge default + optional className. Even though Rule is mostly static, threading `className` through cn keeps the call site idiomatic with other primitives.
- Token-driven only: `bg-rule` (the v2.0 `--color-rule: #E5E2D9` token defined by Plan 09-01 — D-01). NO arbitrary values; NO `border-[1px]`, NO `bg-[#E5E2D9]` (D-09).

The exported component signature (for downstream consumers):
  export function Rule({ className }: { className?: string } = {}): JSX.Element

The render output (semantic + accessible + token-driven):
  <hr aria-hidden="true" className={cn("h-px w-full border-0 bg-rule", className)} />

Why `<hr>` over `<div>`: `<hr>` is semantically a thematic break; `aria-hidden="true"` removes it from the accessibility tree since the rule is decorative (per Pattern 3 in RESEARCH.md).
Why `bg-rule` + `h-px` instead of `border-t border-rule`: avoids the box-model collapse where adjacent margins eat the border; height-based hairline is more predictable for editorial layouts.
