Create the PSI evidence directory:

```
mkdir -p .planning/phases/13-v2-0-qa-go-no-go/evidence/psi
```

Run PSI mobile via the public API (no API key required, but adds rate-limit tolerance):

```
PREVIEW_URL=<from-13-02-evidence>
curl -s "https://www.googleapis.com/pagespeedonline/v5/runPagespeed?url=${PREVIEW_URL}/&strategy=mobile" \
  -o .planning/phases/13-v2-0-qa-go-no-go/evidence/psi/homepage-preview.json
```

Wait 30 seconds, then extract the performance score:

```
node -e "
const data = JSON.parse(require('fs').readFileSync('.planning/phases/13-v2-0-qa-go-no-go/evidence/psi/homepage-preview.json', 'utf8'));
const score = Math.round(data.lighthouseResult.categories.performance.score * 100);
const fcp = data.lighthouseResult.audits['first-contentful-paint'].displayValue;
const lcp = data.lighthouseResult.audits['largest-contentful-paint'].displayValue;
const tbt = data.lighthouseResult.audits['total-blocking-time'].displayValue;
const cls = data.lighthouseResult.audits['cumulative-layout-shift'].displayValue;
const si = data.lighthouseResult.audits['speed-index'].displayValue;
console.log('PSI Mobile Performance Score:', score);
console.log('FCP:', fcp);
console.log('LCP:', lcp);
console.log('TBT:', tbt);
console.log('CLS:', cls);
console.log('Speed Index:', si);
console.log('Gate (>=75):', score >= 75 ? 'PASS' : 'FAIL');
"
```

If the API returns an error (429 rate limit), wait 2 minutes and retry once.

6. Note: "Production post-promote spot-check: run https://pagespeed.web.dev/?url=https://montysinger.com after promote and record here"

Write `13-03-SUMMARY.md` with QA-V2-03 verdict and reference to EVIDENCE.md.

If score is between 65–74: document it clearly as a FAIL but note it for the GO/NO-GO human review — the ROADMAP risk note says "If PSI mobile perf is consistently <90 [sic, <75 for this phase], log it as a known non-blocking caveat — perf optimization can continue post-launch." The GO/NO-GO verdict (plan 13-06) is where the human decides whether to accept or block.
