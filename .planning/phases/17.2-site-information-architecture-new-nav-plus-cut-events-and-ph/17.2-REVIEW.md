### MD-01: Monty Monthly section renders empty on RSS failure with no fallback message

**File:** `src/app/writing/page.tsx:73, 135-141`

**Issue:** `fetchMontyMonthlyIssues` is called unguarded at the top level (line 73). The function catches its own errors and returns `[]`, so the page does not crash — but when `carouselIssues` is `[]`, the "Monty Monthly" `<section>` still renders its `<h3>` heading with an empty carousel container below it. Users see a visible section title ("Monty Monthly") with nothing underneath. The essays section explicitly guards this case (`yearEntries.length === 0 ? <p>No essays yet...</p> : ...`); the newsletter section has no equivalent guard.

**Fix:**

```tsx
{/* Monty Monthly section — folded from deleted /newsletter route (D-04) */}
{carouselIssues.length > 0 && (
  <section className="px-6 md:px-40 pb-16">
    <h3 className="font-mono text-sm uppercase tracking-[0.12em] text-accent mb-[18px]">
      Monty Monthly
    </h3>
    <NewsletterCarousel issues={carouselIssues} />
  </section>
)}

{carouselIssues.length > 0 && <RuleStrong />}
```

Alternatively, render a placeholder message inside the section instead of hiding it, to match the essays empty-state pattern.

### MD-02: WATCHING_ITEMS placeholder data is live on the primary `/uses` page

**File:** `src/lib/watching.ts:23-58`

**Issue:** All 6 items have `channel: "TODO: [Monty to fill in]"`. The `VideoCard` component renders the `channel` prop unconditionally when non-empty (it is non-empty — it contains the TODO string), so every video card on `/uses` shows "TODO: [Monty to fill in]" as channel text visible to real visitors. Additionally, the first item has `id: "PLACEHDR001"` — an invalid YouTube ID — which produces a broken video link (`https://www.youtube.com/watch?v=PLACEHDR001` → "Video unavailable") and an unresolvable thumbnail URL. This data existed previously on the deleted `/watching` route; Phase 17.2 promoted it to the primary "Things I Love" page.

**Fix:** Fill in real YouTube video IDs and channel names before launch, or suppress the `channel` prop when its value begins with "TODO":

```tsx
// In uses/page.tsx, filter placeholder channel text:
<VideoCard
  key={item.id}
  title={item.title}
  channel={item.channel.startsWith("TODO") ? undefined : item.channel}
  href={item.url}
  thumbnail={`https://img.youtube.com/vi/${item.id}/hqdefault.jpg`}
  target="_blank"
  rel="noopener noreferrer"
/>
```

The real fix is replacing the placeholder data in `watching.ts` — the code filter above is a stopgap only.

### LW-06: `NewsletterCarousel` uses `issue.title` as React `key` (duplicate-title risk)

**File:** `src/components/v3/newsletter-carousel.tsx:43, 47`

**Issue:** Both the `<Link>` and `<div>` variants use `key={issue.title}`. RSS feeds occasionally republish items with identical titles (e.g. annual roundups with the same title across years). If two items share a title, React will log a duplicate-key warning and may mis-reconcile the DOM.

    <Link key={key} href={issue.href} ...>
