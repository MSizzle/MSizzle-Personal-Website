    D-04 four-point LCP verification block — perform each check using DevTools on a mobile-emulated load of the preview URL:

    **Assertion 1: LCP element is `<h1>`, never `<canvas>`**
    - In Chrome DevTools: open the preview URL, emulate Moto G Power (375px), run Lighthouse or inspect the PSI "Largest Contentful Paint element" diagnostic

    - In Chrome DevTools Network tab with mobile emulation active (375px), load the preview homepage
    - Filter by JS; search for "three" or sort by size descending
    - The ~885 KB three.js chunk must NOT appear in the network waterfall
    - The `hero-blob-poster.webp` (~5 KB) SHOULD appear as the hero asset
    - If three.js loads on mobile: mark D-04 FAIL

    **Assertion 3: Canvas mounts after LCP**
    - In DevTools Performance tab (with mobile CPU 4x throttle), run a profile of the page load
    - Canvas-related scripts (three.js, HeroBlobCanvas) must not appear in the LCP paint window
    - The requestIdleCallback deferred mount means canvas mounts >200ms after page becomes interactive
    - Record the approximate time offset of canvas mount vs LCP timestamp from the waterfall

    **Assertion 4: `fetchPriority="high"` on the poster image**
    - In DevTools Elements panel, locate the `<img>` rendered by FallbackPoster (the hero-blob-poster.webp element)
    - Confirm the attribute `fetchpriority="high"` is present on the element (lowercase in HTML)
    - Also confirm the `loading` attribute is NOT "lazy" (would negate the priority)
    - If `fetchPriority` is missing: mark D-04 FAIL (Next.js 16 quirk — the `priority` prop alone does not emit this browser resource hint per MEMORY.md)
