LazyMotion strict mode constraint (10-RESEARCH §"motion/react 12.38 API Surface" → "LazyMotion + m vs motion"):
- src/components/providers/motion-provider.tsx wraps in `<LazyMotion features={domAnimation} strict>`.
- ANY motion component rendered inside this tree MUST use `m.*` not `motion.*`.
- Example correct import: `import { m, useReducedMotion, type Variants } from "motion/react";`

sessionStorage SSR-safety pattern (10-RESEARCH §"Pitfall 3"):
- DO NOT read sessionStorage during render — `typeof window === 'undefined'` will throw.
- Read in `useEffect(() => { ... }, [])` only.
- Set initial state to a sentinel ("pending") and transition to "animate" or "skip" inside the effect.

Hydration-safe rendering (10-RESEARCH §"Pitfall 4"):
- Server renders the final static manifesto.
- Client first render matches the server (phase === "pending" branch returns static markup).
- After mount, useEffect transitions phase to "animate" → animation kicks in cleanly.

useReducedMotion (10-RESEARCH §"motion/react 12.38 API Surface"):
- Returns boolean | null. null on SSR; true/false after client mount.
- Treat null as "not yet known" — render static; then transition in useEffect.

matchMedia for breakpoint (10-RESEARCH §"Mobile Manifesto Line-Break Recommendation" → approach #2):
- Initial state = desktop lines (matches SSR rendering of a desktop user).
- useEffect with `window.matchMedia("(max-width: 767px)")` swaps to mobile lines after mount; listener cleans up on unmount.

Per-character delay formula (D-03 + RESEARCH §"Note on the delay formula"):
- delay = cumulativeCharIndex × 0.018s
- cumulativeCharIndex = sum of all prior lines' character counts + current charIdx
- This makes the wave continuous across the line break.

       useEffect(() => {
         const already = sessionStorage.getItem(SESSION_FLAG);

           setPhase("animate");

       }, []);

       ```
       useEffect(() => {
         const mql = window.matchMedia("(max-width: 767px)");
         const update = () => setLines(mql.matches ? MOBILE_LINES : DESKTOP_LINES);
         update();
         mql.addEventListener("change", update);
         return () => mql.removeEventListener("change", update);
       }, []);
       ```

Apply different classes by checking `lines.length === 3` (3 = mobile, 2 = desktop). Provide:
       - `initial={phase === "animate" ? { opacity: 0 } : { opacity: 1 }}`
       - `animate={{ opacity: 1 }}`
       - `transition={{ duration: FADE_FALLBACK_DURATION, ease: "easeOut" }}`
       Inside: `{lines.map((line, i) => <span key={i} className="block whitespace-nowrap">{line}</span>)}`

       Branch B — phase === "pending" OR phase === "skip":
       Render a plain `<h1>` (not m.h1) with the appropriate manifesto styling (same conditional class logic as Branch A). Inside: same line spans.
       Reason: This is the SSR-stable branch. Server renders this; client first paint matches; no hydration flicker.

       Branch C — phase === "animate" AND !shouldReduceMotion:
       Render `<m.h1 className="..." initial="hidden" animate="visible" variants={container}>` with container variants = `{ hidden: {}, visible: { transition: { staggerChildren: 0 } } }` (we hand-set delays, no global stagger).

       Inside, for each line: `<span key={lineIdx} className="block whitespace-nowrap overflow-hidden">` containing `Array.from(line).map((char, charIdx) => (...))`. Compute `cumulativeCharIdx = lines.slice(0, lineIdx).reduce((s, l) => s + l.length, 0) + charIdx`. Then `const delay = cumulativeCharIdx * STAGGER_PER_LETTER;`.

       Each character: `<m.span key={charIdx} className="inline-block" variants={item} custom={delay}>{char === " " ? " " : char}</m.span>` (use a non-breaking space U+00A0 for spaces so the inline-block letter retains layout width; do NOT use a bare " " — it can collapse in some browsers when the parent has overflow hidden).

       Where `item` Variants is:
       ```
       const item: Variants = {
         hidden: { y: "110%", opacity: 0 },
         visible: (delay: number) => ({
           y: "0%",
           opacity: 1,
           transition: {
             y:       { duration: TRANSFORM_DURATION, ease: [0.2, 0.7, 0.2, 1], delay },
             opacity: { duration: OPACITY_DURATION,  ease: "easeOut",          delay },
           },
         }),
       };
       ```
