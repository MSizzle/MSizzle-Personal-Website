## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Critical] Added .wrap, .selective, .selective b, .footmark, footer.site to globals.css**
- **Found during:** Task 1 pre-flight
- **Issue:** Plan 01 added the full sketch CSS class library but `.wrap` (structural container), `.selective` (footer selective line), `.selective b` (accent bold), `.footmark` (copyright mark), and `footer.site` (padding) were not included. Section components reference `className="wrap"` and `className="selective"` per the plan spec; without CSS definitions the layout would span full width with no max-width centering.
- **Fix:** Appended five CSS rule blocks to `src/app/globals.css` before the responsive overrides section, directly from the sketch spec (lines 30, 152-157).
- **Files modified:** `src/app/globals.css`
- **Commit:** 0dcc36f

**2. [Rule 1 - Bug] Removed em dashes from JSX comments to pass file-wide grep**
- **Found during:** Task 1 and Task 3 verification
- **Issue:** The automated verification (`! grep -q '—'`) checks the entire file. JSDoc comment lines containing "—" for readability caused the check to fail.
- **Fix:** Replaced em dashes in comments with colons/commas/no-separator equivalents.
- **Files modified:** `src/components/home/section-loves.tsx`, `src/components/home/section-footer.tsx`
- **Commit:** 0dcc36f, 723eb0b

**3. [Rule 1 - Bug] Removed "use client" string from comment in section-loves.tsx**
- **Found during:** Task 1 verification
- **Issue:** Automated check `! grep -q 'use client'` found the string in a JSDoc comment: `Server Component, no "use client"`. The check checks the entire file, not just code directives.
- **Fix:** Changed comment to `Server Component (RSC only, no client boundary)`.
- **Files modified:** `src/components/home/section-loves.tsx`
- **Commit:** 0dcc36f

**4. Structural decision: SectionLoves returns React Fragment, not section element**
- **Found during:** Task 1 planning
- **Issue/Decision:** The plan specifies "returning beat CONTENT; orchestrator (Plan 08) supplies the band section + id." Current section-loves.tsx wrapped in a `<section>`. Switched to returning a Fragment `<>div.wrap + PhotoMarquee</>` so Plan 08 can compose it inside `<section className="band-dark beat" id="loves">`.
- No bug, no rule violation. Intentional structural improvement per the interface spec.
