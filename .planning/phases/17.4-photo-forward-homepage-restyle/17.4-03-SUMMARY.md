# Phase 17.4 Plan 03: Scroll/Ambient Motion Islands Summary

IntersectionObserver scroll-reveal island (ScrollReveals) and photo-card marquee island (PhotoMarquee) built as minimal client islands, both honoring prefers-reduced-motion and importing no WebGL or Lenis.

## What Was Built

### Task 1 — ScrollReveals (D-07, D-08)

`src/components/home/scroll-reveals.tsx` is a headless `"use client"` island that exports `ScrollReveals()` and returns `null`. On mount it:

1. Collects all `.reveal, .slide, .shadowed` elements that do not already have `.in`.
2. **Reduced-motion path (D-08):** If `window.matchMedia('(prefers-reduced-motion: reduce)').matches`, immediately adds `.in` to all targets and returns — no observer is created.
3. **Animated path (D-07):** Creates one `IntersectionObserver` with `{threshold: 0, rootMargin: '0px 0px -38% 0px'}` (matching the sketch), observes all targets, and on `isIntersecting` adds `.in` + unobserves (fire-once). Disconnects on unmount.

This single global observer wires every section's slide-in photos without any per-component observer — minimal client surface.

### Task 2 — PhotoMarquee (D-07, D-08)

`src/components/home/photo-marquee.tsx` is a `"use client"` island that exports `PhotoMarquee({ items: string[] })`. It:

1. Doubles `items` back-to-back so the CSS `slide` keyframe (`translateX 0 → -50%`) loops seamlessly.
2. Renders `<div className="marquee">` → `<div className="track" style={{ gap: 18, animationPlayState: ... }}>` with fixed-width photo cards (`flex: 0 0 clamp(220px,25vw,310px)`).
3. Each card: `.photo` div (aspect-ratio 3/4) with `.img`, icon, and `.cap` caption.
4. Second-half (duplicate) cards receive `aria-hidden="true"`.
5. `useReducedMotion()` from `motion/react` pauses the CSS animation as a React-level gate alongside the Plan-01 CSS `@media (prefers-reduced-motion: reduce)` guard (belt-and-suspenders).

## Deviations from Plan

### Intentional Scoping Decision

**Inlined photo card markup in PhotoMarquee (no import from photo.tsx)**
- **Found during:** Task 2 pre-flight check
- **Issue:** Plan 02 (`photo.tsx`) and Plan 03 run in parallel (both wave 2). `photo.tsx` does not exist in this worktree at execution time; importing from a non-existent module would cause `npx tsc --noEmit` to fail, blocking the verification gate.
- **Fix:** Inlined the `.photo` card markup (`.img`, `.icon`, `.cap` elements) directly in `photo-marquee.tsx`. The visual output is identical to using the `Photo` component. After the wave 2 merge, a subsequent plan (or Plan 07 wiring) can optionally refactor to import from `photo.tsx`.
- **Files modified:** `src/components/home/photo-marquee.tsx`

## Known Stubs

None. Both islands are complete functional units. The photo cards use placeholder styling (hatch gradient via `.photo .img` CSS) that will be swapped for real photography in a future asset pass — this is intentional per the phase scope (D-07: "Placeholder blocks stand in for real photography").

## Threat Flags

None. Both islands operate purely on client-side DOM state (scroll position, viewport intersection). No network calls, no user data processed, no new trust boundaries introduced.
