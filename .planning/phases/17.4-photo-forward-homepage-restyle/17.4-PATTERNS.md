### `src/app/globals.css` — Token re-theme (D-01) + font map (D-02)

**Analog:** its own current `@theme inline` block (lines 20–36, 48–52, 88–91). Confirmed
**fully token-driven** — a repo-wide grep found **zero** hardcoded cobalt hexes in any
home/v3 component; every cobalt value lives only in this file. D-01 is a pure token swap.

**Exact lines to flip cobalt `#1a4fd6` → Vermilion `#e5411f` family** (sketch accent tuple
is `['#e5411f','#c8381a','#a52d13','rgba(229,65,31,.32)']`, sketch line 383):

```css

--accent-hover:         #1740ad;   /* → #c8381a */
--accent-deep:          #14328a;   /* → #a52d13 */
--accent-glow:          rgba(26,79,214,0.35);  /* → rgba(229,65,31,0.32) */
```

## New Pattern — No Analog (planner: build fresh, flag as landmine)

These have **no existing implementation** in the codebase. Sketch is the only reference.

### 1. IntersectionObserver scroll-reveal / slide-in photos (D-07)
**No IO anywhere in `src/`** (grep confirmed — only mentioned in a spec `.md`). The nearest
analog is `src/components/v3/reveal.tsx`, which uses **`motion/react` `whileInView`**, not a
raw `IntersectionObserver`. Two viable routes for the planner:
- **Reuse `motion`**: wrap photos in a `Reveal`-style `m.div` with `initial={{opacity:0, x:±72}}`
  `whileInView={{opacity:1,x:0}}` and the reduced-motion short-circuit (reveal.tsx lines 26–50).
  This keeps the existing LazyMotion stack and reduced-motion handling for free.
- **Match sketch literally** (IO + CSS `.slide`/`.shadowed.in` classes, sketch JS 444–445):
  a small `"use client"` island that observes elements and toggles an `.in` class; CSS in
  globals does the transform + `box-shadow` settle (sketch 168–188).
The **even black drop-shadow settle** (`.shadowed.in .photo` box-shadow, sketch 174–176) and
alternating L/R slide (`--sx:-72px` / `.from-right{--sx:72px}`) are both new.
**Reduced-motion (D-08):** whichever route, honor `prefers-reduced-motion` — sketch renders
the static settled state (photo visible, shadow present, no transform), matching reveal.tsx's
reduced-motion branch.

### 2. Scroll-triggered sticky mini-nav with Subscribe CTA (D-10)
**No scroll-show/hide nav exists.** `nav/navigation.tsx` is a `fixed` mobile bar +
`EditorialHeader`, but has **no scroll listener** and no show-past-hero behavior. The sketch
(CSS 195–206, JS 452–454) uses `window.scrollY > innerHeight*0.82` to toggle a `.show` class
that slides the bar down (`transform:translateY(-100%)` → `none`). This is a **new client
island**: a `"use client"` component with a passive scroll listener (or IO sentinel on the
hero) toggling visibility, carrying the persistent Vermilion **Subscribe** CTA →
`https://montymonthly.substack.com`. **Landmine:** must not conflict with the existing
`fixed top-0 z-50` mobile `<header>` in navigation.tsx — coordinate z-index/stacking (sketch
uses `z-index:9000`).

### 3. Monty Monthly carousel — arrows + dots + scroll-position sync (D-09)
`src/components/v3/newsletter-carousel.tsx` is the closest analog: native
`[scroll-snap-type:x_mandatory]` + `[scroll-snap-align:start]` flex cards (lines 21, 40) — but
it's a **Server Component with no JS controls**. The sketch adds prev/next buttons that
`scrollBy`, dot indicators, and a scroll listener that computes the nearest-centered card to
light the active dot (`syncDots`, sketch JS 435–441). This becomes a **client island**;
reuse the snap-track CSS from newsletter-carousel and add the control logic. Includes a
Vermilion **subscribe card** as the last snap item (sketch 137–143, 432–434).

### 4. Auto-inverting rail box + band inversion (D-03, D-05)
The current single fixed theme has **no dark-band mechanism**. The sketch's `.band.dark`
(CSS 34–37) *locally overrides* `--color-text`, `--color-bg`, `--color-border` etc. so
child components auto-invert. The **rail box** (`.rail-box`, CSS 94–97) uses
`background:var(--color-text); color:var(--color-bg)` so it flips to the opposite of
whatever band it sits in — one component, two appearances. `v3/section-label.tsx` (the
`numeral` layout) is the nearest structural analog but does **not** invert. See Shared
Patterns for the token-override approach the planner must choose.

## Shared Patterns

### Band inversion (dark/light alternation) — applies to Building, Loves, Footer, sticky-nav
**Source of intent:** sketch CSS lines 32–38.
```css
.band.dark{
  --color-text:#f5f3ee;--color-text-dim:rgba(245,243,238,.76);--color-text-muted:rgba(245,243,238,.54);
  --color-border:rgba(255,255,255,.15);--color-border-strong:rgba(255,255,255,.32);
  background:#141416;color:var(--color-text)}
```
**No such override exists today** — globals.css defines one fixed light theme. The planner
must introduce a dark-band mechanism. In Tailwind-v4-token terms, that means a `.band-dark`
utility/class (or a wrapper that re-declares the `--color-*` custom properties) so existing
token classes (`text-text`, `border-border`, `text-text-muted`) auto-invert **without
rewriting each child**. This is the single highest-risk new pattern — every section component
already uses these token classes, so a correct override makes reskin cheap; a wrong one means
per-component color hardcoding (avoid — violates the token-driven principle confirmed in D-01).

### Reduced-motion gate — applies to every animated island (D-08, hard requirement)
**Source:** `src/components/v3/reveal.tsx` lines 26–50 and `src/components/v3/marquee.tsx`
lines 12, 37–41.
```typescript
// reveal.tsx — the canonical short-circuit
const shouldReduceMotion = useReducedMotion();
if (shouldReduceMotion) {
  return <div className={className}>{children}</div>;   // static, fully visible
}
return <m.div initial={{opacity:0,y:30}} whileInView={{opacity:1,y:0}} ... />;
```
```typescript
// marquee.tsx — animation only when motion allowed
const reducedMotion = useReducedMotion();
<div className={cn("inline-block", !reducedMotion && "[animation:scroll_30s_linear_infinite]")}>
```
Every new island (slide-in photo, sticky-nav entrance, carousel auto-behavior, marquee,
ken-burns, breathe, blob drift) MUST have a reduced-motion path that leaves the **static
layout intact** (D-08). The sketch mirrors this with `@media(prefers-reduced-motion:reduce)`
(CSS 185–188) forcing `opacity:1; transform:none` and killing keyframe animations. Note:
`MotionProvider` already sets `<MotionConfig reducedMotion="user">` and uses `LazyMotion
strict` — new islands **must import `m` (not `motion`)** from `motion/react` or LazyMotion
strict throws at runtime.

### LazyMotion `m` constraint — applies to any `motion/react` island
**Source:** `src/components/providers/motion-provider.tsx`.
```typescript
<LazyMotion features={loadDomAnimation} strict>
  <MotionConfig reducedMotion="user">{children}</MotionConfig>
</LazyMotion>
```
`strict` mode means components must use `m.div` (not `motion.div`). reveal.tsx line 4/37
already follows this. Any new motion-based reveal must too.

### Scroll-snap track — applies to Monty Monthly carousel + loves marquee
**Source:** `src/components/v3/newsletter-carousel.tsx` lines 21, 40.
```typescript
<div className="flex gap-[18px] overflow-x-auto [scroll-snap-type:x_mandatory] pb-[18px]">
  ...
  <div className="flex-[0_0_300px] [scroll-snap-align:start] border border-border bg-bg-2">
```
Reuse this Tailwind arbitrary-property snap idiom; the sketch's `.mm-track` (CSS 125–129)
adds `scroll-behavior:smooth` + hidden scrollbar + `scroll-snap-align:center`.

### External-link safety — applies to all outbound links (preserved invariant)
**Source:** used consistently in section-building/work/footer.
```tsx
<a href="https://prometheus.today" target="_blank" rel="noopener noreferrer">
```
`section-work.test.tsx` (T-17.1-02) asserts `rel` contains `noopener` + `noreferrer` — keep
on every external anchor (Prometheus, Substack, GitHub, LinkedIn, X).
